# cc-rc

Docker image + Helm chart for running headless [Claude Code](https://claude.ai/) agents
in Kubernetes, one `StatefulSet` per GitHub repo, egress-restricted through a Squid proxy.

## Image

`ghcr.io/vince-riv/cc-rc`. Built by `.github/workflows/docker-build.yml` on every push to
`main` (`latest`, `sha-<short>`) and PR (`pr-<n>`). Ubuntu 26.04, non-root `dev` user
(uid/gid 1000), no sudo. Ships `git`, `gh`, `screen`, `rsync`, Go 1.25/1.26, and Claude
Code (native install, auto-update on). `WORKDIR /workspace`. Also ships a baked-in
`~/.claude/CLAUDE.md` that has every coding-task agent open a Draft PR before writing
code and keep a progress ledger in its description, plus a `cc-rc-pr-update` helper
(on `PATH`) that creates/updates that PR consistently — see `.claude/CLAUDE.md` and
`scripts/cc-rc-pr-update.sh`.

## Chart

`charts/cc-rc`. Released by `.github/workflows/chart-release.yml` on `X.Y.Z[-suffix]` tag
pushes — `-rcN` suffixes publish a GitHub prerelease, other suffixes publish the chart
with no release, no suffix is a normal release. Published to
`oci://ghcr.io/vince-riv/charts/cc-rc` and `https://vince-riv.github.io/cc-rc/`
(`helm repo add cc-rc ...`).

```sh
helm install cc-rc oci://ghcr.io/vince-riv/charts/cc-rc --version 0.3.1 \
  --set repos[0].org=myorg --set repos[0].repo=myrepo \
  --set github.tokens.myorg=ghp_... \
  --set git.name="CI Bot" --set git.email=ci@example.com
```

Required values: `github.tokens` (one GitHub PAT per org - see
`scripts/manage-github-tokens.sh` for a `values.yaml`-free way to manage these) or
`github.existingSecret`, `git.name`/`git.email`, and
at least one `repos[]` entry (`org`/`repo`). Full reference in
[`charts/cc-rc/README.md`](charts/cc-rc/README.md) (generated by `helm-docs` from
`values.yaml`/`README.md.gotmpl` — edit the `.gotmpl`, not the rendered file).

### Architecture

- **Squid `Deployment`** — the only workload with unrestricted egress. `proxy.allowList`
  empty = open web on `proxy.allowedPortsWhenOpen`; non-empty = strict allow-list, ports
  80/443 only. `proxy.denyList` and `proxy.defaultBlocked` (`cluster.local`, RFC1918)
  always win. `github.com:22` (git+ssh) is always allowed, in both modes, tunneled
  through squid via `CONNECT` — see the SSH deploy key Job below. Access/cache logs go
  to `kubectl logs`/stern.
- **SSH deploy key `Job`** (pre-install/pre-upgrade hook) — generates one ED25519 key
  shared by every `repos[]` entry, registers it against a GitHub account using one org's
  PAT (`sshKey.tokenOrg`, defaults to `repos[0].org`'s), and stores it in a `Secret`.
  Idempotent (no-op once that `Secret` exists) and self-rolling-back (deletes the
  just-added GitHub key again if the `Secret` write fails).
- **Per-repo `StatefulSet`** (replicas: 1) — `NetworkPolicy` permits egress only to Squid
  + cluster DNS (git+ssh tunnels through squid too, no separate rule needed). PVCs:
  `/home/dev` (`storage.homeSize`) and `/workspace` (`storage.workspaceSize`).
  Orchestration scripts (`files/scripts/*.sh`) are ConfigMap-mounted, not baked into the
  image, so a custom `image.repository`/`tag` only needs to provide the underlying
  tools.
  - `seed-home` init container: syncs the image's `~/.claude/` onto the PVC every boot
    (overwrite, never delete extras — credentials/session state persist); resets
    everything else to match the image, excluding `~/.cc-rc/` and `~/.claude.json`.
  - `seed-ssh` init container: copies the deploy key onto `~/.ssh/id_ed25519` (`0600`,
    `~/.ssh` `0700`) every boot, seeds `~/.ssh/known_hosts` with GitHub's host keys only
    if missing, and (re)writes `~/.ssh/config` to tunnel git+ssh through squid.
  - `clone-repo` init container: clones `org/repo` over SSH into `/workspace/repo`,
    idempotent.
  - Agent container: `GH_TOKEN` comes from the `Secret` key matching this
    StatefulSet's own `repos[].org` (one PAT per org - see "Configuring GitHub auth" in
    `charts/cc-rc/README.md`). On first boot, starts `claude --no-chrome` in a detached
    `screen` session and waits for you to run `/login` then `claude remote-control`
    inside it (`kubectl exec -it <pod> -- screen -r claude-login`); marks
    `~/.cc-rc/login-complete` and exits to restart into steady state. Subsequent boots
    run `claude remote-control --name --permission-mode --spawn --capacity` (from
    `remoteControl.*`/`repos[].remoteControl.*`) directly; readiness probe checks the
    process is running, container self-exits after 45s down.

## Development

```sh
helm lint charts/cc-rc
helm unittest charts/cc-rc
helm-docs -c charts        # regenerate charts/cc-rc/README.md after editing .gotmpl/values.yaml
actionlint .github/workflows/*.yml
docker build -t cc-rc .
```
